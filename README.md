# security-portfolio

网络空间安全方向在校生。这里放我打过靶场的复现笔记和一些学习沉淀。

⚠️ 所有内容仅用于**授权测试与安全学习**。靶场域名、账号、凭据、flag 与完整攻击载荷均已脱敏或不收录。

---

## 先看这两条框架

这个仓库是按两条判断框架组织的——**每一篇笔记都是其中一条的实例**。框架的详细说明与覆盖情况见 [FRAMEWORK.md](FRAMEWORK.md)。

**框架一 · getshell 三元组：能写进去 + 能访问到 + 能被解析。**
三者缺一，利用不成立。适用于文件上传、WAR 部署、`into outfile` 写 webshell 三条路径。

**框架二 · 绕过的统一原理：过滤发生在字符串层，解析发生在语义层，两者不一致处就是缝隙。**
关键词双写、变量拼接与参数交叉引用、路径穿越（`..\`）、`%00` 截断，都是这条原理的不同形态。

所以写笔记的顺序是：先判断"它归到哪条框架"，再写现象与步骤；而不是先记 payload 长什么样。

## 仓库约定

- 笔记统一六段：**现象 → 原理 → 复现 → 危害 → 修复 → 延伸**；不写"我学会了某某"这类没有信息量的句子
- 「原理」一节要把框架走完：归到哪条、为什么成立；不写空泛的"危害很大"
- 「复现」只写**做了什么动作 → 观察到什么现象 → 由此得出什么判断**，不出现可直接复制使用的完整载荷
- 敏感信息一律脱敏：目标地址写 `<target>`、路径写 `<path>`、账号写 A / B
- 归类要准——归类决定修复方向，归错了修复就全错（见 03 篇）
