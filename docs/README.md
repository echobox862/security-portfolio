# Docs · 学习沉淀

> Writeups 记录"打过的靶场"，Docs 记录"搞懂的概念与踩过的坑"。这一块不如靶场笔记亮眼，但它最能让面试官判断**基础是否扎实**——因为靶场可以照着复现，概念长文和踩坑记录没法照抄。

## 适合放这里的四类笔记

| 类型 | 例子 | 为什么值钱 |
|---|---|---|
| **原理长文** | 「HTTP 无状态这件事，怎么一路推导出 CSRF 和越权」 | 展示理解机制，而不是背结论 |
| **对照表** | 「命令执行里几个执行函数在回显上的差异」 | 一看就知道是真用过的人总结的 |
| **踩坑记录** | 「Burp 改了包为什么打不通：请求体长度没跟着改」 | 踩坑记录最真实，也最容易帮到别人 |
| **版本勘误** | 「教材说 MySQL 直接用写文件语法就能落地脚本，但在新版本上默认走不通」 | 展示你会核实信息，而不是照抄教程 |

## 命名与格式

- 文件名：`主题.md`，例如 `http-csrf-relationship.md`、`mysql-secure-file-priv.md`
- 正文用「**问题 → 结论 → 依据 → 延伸**」四段
- 涉及引用时附来源（官方文档优先），并注明查阅日期

## 示例结构

```markdown
# 为什么新版本 MySQL 上用写文件语法落地脚本走不通

## 问题
教程里说拿到注入点后可以用写文件语法把脚本写到 Web 目录，
但我在 MySQL 8 的环境上直接报错。

## 结论
MySQL 从 5.7 起引入、8.0 起严格执行一个限制文件读写目录的配置变量，
默认值会完全禁止导入导出，因此这两条路都走不通。

## 依据
- 官方文档：MySQL 8.0 安全部署指南中对该变量的说明（默认值即禁用）
- 实测：查询该变量的当前值确认

## 延伸
即使变量允许，写文件还额外需要：账号具备文件写入权限、目标目录对数据库进程可写、
写入路径在允许范围内。这三条与文件上传是同一套逻辑——
能写进去 + 能访问到 + 能被解析（见 FRAMEWORK.md 框架一）。
```

> 这篇示范的写法同时做了两件事：**会查官方文档**，以及**能从一次踩坑抽象出可复用的判断**——后者正是把个案归到框架上的过程。
