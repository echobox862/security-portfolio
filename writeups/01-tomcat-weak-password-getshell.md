# Tomcat 弱口令 && 后台 getshell

| 项 | 内容 |
|---|---|
| 漏洞类型 | 弱口令 + 任意文件部署（后台 getshell） |
| 环境 | 授权靶场环境（Tomcat 管理后台） |
| 工具 | 浏览器、Burp Suite、WebShell 管理工具 |
| 复现日期 | 2025-06-25 |
| 风险等级 | **高危**——可直接获得服务器命令执行能力 |

> 靶场域名与账号已脱敏。

---

## 一、现象

访问目标 Tomcat 首页，管理后台 `/manager/html` 使用弱口令 `tomcat/tomcat` 即可登录。进入后台后可部署 WAR 包，部署后其中的 JSP 文件直接被解析执行——最终取得服务器控制权限。

## 二、原理

这条链子由**两个独立缺陷叠加**而成，缺一不可：

**缺陷一：管理后台存在弱口令**

Tomcat 的管理功能由 `manager` 应用提供，账号配置在 `conf/tomcat-users.xml` 中。较新版本的 Tomcat 该文件默认**不配置任何账号**（相关配置行保持注释状态），但历史版本、镜像模板或运维自行配置时，常保留 `tomcat/tomcat`、`admin/admin` 这类默认凭据。**弱口令的本质不是"密码太简单"，而是"默认值从未被修改"**——这正是安全配置错误（Security Misconfiguration）的典型形态。

**缺陷二：Manager 的 deploy 功能把上传能力变成了代码执行能力**

Tomcat Manager 提供了对 Web 应用的部署/启动/停止功能，其设计目的是方便运维发版。它接受 `.war` 包并**自动解压到 `webapps` 目录后部署**。而 `.war` 里可以包含 `.jsp` 文件，JSP 又是被 Tomcat 正常解析的服务端脚本——于是"上传一个包"直接等价于"在服务器上放了一个可执行脚本"。

**用「getshell 三元组」复盘这条链**：

| 条件 | 在本例中如何满足 |
|---|---|
| 能写进去 | Manager 的 deploy 功能本身就是为了写文件而设计的 |
| 能访问到 | WAR 自动解压到 `webapps`，通过 `/应用名/文件名` 即可访问 |
| 能被解析 | 上传的是 `.jsp`，由 Tomcat 自身解析 |

**三个条件全部天然满足**——这就是为什么"后台弱口令"看起来只是个口令问题，实际后果却是服务器失陷。

## 三、复现步骤

1. 访问 Tomcat 首页，确认服务存在
2. 访问管理界面 `/manager/html`，使用弱口令 `tomcat/tomcat` 登录成功
3. 将测试用 JSP 文件打包为 `.war`
4. 在管理界面下拉找到 **WAR file to deploy** 部署位置，选择并部署该 WAR 包
5. 部署后访问 `/应用名/应用名.jsp`，页面正常打开
6. 使用 WebShell 管理工具连接该 JSP，获得命令执行能力
7. 在文件系统中逐级返回上层目录，定位到目标文件与 flag

**关键操作点（脱敏）**

```
访问：http://<lab-domain>/hack520/hack520.jsp     ← 部署后生成的访问路径
连接：使用 WebShell 管理工具，密码取自部署的 JSP 文件
```

> **部署路径规律值得记**：WAR 包名会成为应用上下文路径，包内的 JSP 名会成为访问文件名。这是"路径可知"条件的来源。

## 四、危害

- **服务器完全失陷**：拿到了 JSP 执行环境，等同于获得 Web 服务权限下的任意命令执行
- **数据泄露**：可读取配置文件（数据库连接串、密钥）、业务数据
- **横向渗透跳板**：以该服务器为起点探测内网
- 本例中直接读取到了靶场目标文件，证明"从弱口令到读取敏感文件"的完整链路成立

## 五、修复建议

| 层级 | 措施 |
|---|---|
| **配置** | 删除或禁用 Tomcat 默认/演示账号；管理后台不对外网开放，限制来源 IP |
| **配置** | 生产环境不部署 `manager` / `host-manager` 应用（用不到就删掉，最彻底） |
| **代码/运行** | Tomcat 以低权限用户运行，避免服务被拿下即等于主机沦陷 |
| **运维** | 强制修改默认凭据、启用强密码策略；对后台登录做失败次数限制与审计告警 |
| **监测** | 关注 `webapps` 目录异常新增文件、管理后台的异常部署请求 |

**优先级说明**：**"不对外暴露管理后台 + 不部署 manager 应用"是配置层措施，改变了能力边界，比单纯改强密码更根本。**

## 六、延伸

**这是一次"弱口令不等于低危"的实例。** 弱口令本身只是一个入口，真正决定危害的是它能打开什么功能：

- 本例中它打开的是 **文件部署** → 直接 getshell
- 如果打开的是 **文件管理** → 相当于任意文件上传
- 如果打开的是 **系统监控/日志** → 可能造成信息泄露

**面试时的价值**：这条链能同时讲清三件事——① 默认配置不改就是漏洞；② 管理功能本身就是高权限攻击面；③ 上传能力与执行能力一旦叠加，风险等级立刻跃升。也与本项目其他实验（文件上传 getshell、SQL 写马）共享同一套「能写 + 能访问 + 能解析」的判断框架。
