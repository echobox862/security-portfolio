## 命名与组织约定

- 文件名：`序号-目标-关键手法.md`
- 一篇只讲一个点，不写"综合大杂烩"
- 目标地址统一写 `<target>`、路径写 `<path>`、账号写 A / B，**不写真实信息**
- 载荷只写**机制与观察点**，不出现可直接复制使用的完整载荷；可用的后门代码不进仓库

## 三条写作纪律

1. **只写自己亲手复现过的**。看教程抄来的笔记不算——面试一追问细节就会露。
2. **每个结论后面跟一句"为什么"**。比如不写"改 Content-Type 就能绕过"，而要写清楚"这个字段由客户端声明、可伪造，服务端拿它做判断就等于信任了不可信输入"。
3. **归类要准**。第 03 篇就是例子：原报告把参数注入 RCE 归为"文件上传"，而归类决定修复方向——按上传去修，措施对这个漏洞完全无效。
