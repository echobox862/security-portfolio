## 命名与组织约定

- 文件名：`序号-目标-关键手法.md`
- 一篇只讲一个点，**不写"综合大杂烩"**
- 复现步骤里的目标地址统一写成 `<target>` / `<lab-domain>`，**不写真实地址**
- 载荷只保留**能说明原理的最小形态**；可用的完整后门不进仓库

## 三条写作纪律

1. **只写自己亲手复现过的**。看教程抄的笔记不算，因为面试一追问细节就露。
2. **每个结论后面跟一句"为什么"**。比如不写"改 Content-Type 就能绕过"，而要写"因为这个字段由客户端声明、可伪造，服务端用它判断就等于信任了不可信输入"。
3. **归类要准**。第 03 篇就是例子——原报告把参数注入 RCE 归为"文件上传"，而归类错了，修复方向就会全错。**这一处修正本身就是笔记的价值。**
