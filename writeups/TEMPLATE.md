## 一、现象

【一句话说清"发现了什么"。例：在头像上传处，把文件名改成 `shell.php` 后直接上传成功，且该文件可被访问并执行。】

## 二、原理

【这段最值钱，也是最容易写空的地方。要回答三个问题：】

1. **漏洞的成因是什么？** 【例：服务端用黑名单校验后缀，而黑名单只列出 `.php`，未覆盖 `.phtml` 等同样会被解析的后缀。】
2. **为什么攻击手法能生效？** 【例：过滤逻辑是"把 `php` 替换为空"且只执行一次，因此构造 `pphphp` 经一次替换后恰好剩下 `php`。】
3. **防御为什么没拦住？** 【例：黑名单的固有缺陷是"永远列不全"；过滤只做一次则一定能被构造绕过。】

> 检验标准：把这段发给一个没做过这道题的同学，他能不能看懂"为什么能打通"。

## 三、复现步骤

1. 【进入某功能点，观察上传行为】
2. 【判断校验类型：点击上传有没有产生请求？能否上传未知后缀？】
3. 【构造并提交 payload】
4. 【验证结果：能否访问、能否解析、返回内容是什么】

**关键请求（脱敏）**

```
POST /upload.php HTTP/1.1
Host: <target>
Content-Type: multipart/form-data; boundary=----x

------x
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/png

<?php echo "poc-test"; ?>
------x--
```

> 载荷只留**能证明漏洞存在**的最小内容（如 `echo`），不写可用后门。

## 四、危害

【从"能不能被利用"推到"会造成什么后果"。例：结合上传目录可被 Web 访问与 `.php` 可被解析两个条件，攻击者可获得服务器命令执行能力，进一步读取业务数据、横向渗透。】

**利用前提清单**（写清楚更显专业）

- [ ] 能上传恶意文件
- [ ] 上传路径可知
- [ ] 文件可被访问
- [ ] 文件可被解析

## 五、修复建议

| 层级 | 措施 |
|---|---|
| 代码 | 改用**白名单**校验后缀；对上传文件重新命名为随机串 |
| 配置 | 上传目录**禁止执行脚本** |
| 其他 | 校验文件真实内容（魔数）；限制上传大小与类型 |

> 推荐按「代码 → 配置」两层写，**配置层往往比代码层更有效**（它改变了能力边界，而不是试图过滤输入）。

## 六、一点延伸（可选但很加分）

【关联到相邻知识点。例：同一套"过滤只做一次"的缺陷，在 XSS 里表现为 `<<script>` 绕过；在 SQL 注入里表现为关键字双写 `UNIunionON`。它们的共同原理是——过滤发生在字符串层，而解析发生在语义层。】
